# 04 — API Routes, Services, and Backend Traceability

## 1. Backend Architecture Overview

The backend is implemented as **78 Next.js App Router route handlers** under `app/api/**/route.{js,ts}` executing on the Node.js runtime (`runtime = 'nodejs'`), supported by **28 service modules** in `lib/services/*.js`, **3 security modules** in `lib/security/*.js`, and **17 PostgreSQL repositories** in `lib/repositories/*.js`.

### Request Authentication & Subscription Gatekeeping (`lib/security/authenticate.js`)
When any route calls `await getAuthenticatedUser(request)`:
1. The `milk_session` cookie is verified via HMAC-SHA256 (`lib/security/session.js`).
2. The user row is loaded from PostgreSQL (`userRepository.findById(session.id)`).
3. If the user does not exist or `account_status === 'suspended'`, `null` is returned (causing the route to return `401`).
4. If `user.role === 'super_admin'` or `user.email` matches `process.env.SUPER_ADMIN_EMAIL`, `user.role` is normalized to `'super_admin'`.
5. For non-`super_admin` users, if `request.url` is not matched by `isSubscriptionRecoveryRequest(request)` (`lib/security/authenticate.js:33-45`), `await requireActiveSubscription(user)` (`lib/security/subscription-access.js`) is automatically executed, throwing HTTP `402 SUBSCRIPTION_REQUIRED` if `effective_status` is `'suspended'` or `'expired'`.

> [!WARNING]
> **Critical Runtime Crash Finding (`F-001`, `F-002`, `F-003`)**: Because `getAuthenticatedUser(request)` already enforces `requireActiveSubscription(user)`, redundant calls to `await requireActiveSubscription(user)` in `app/api/milk/[id]/route.js:34,56`, `app/api/deductions/[id]/route.js:31,50`, and `app/api/collector-assignments/[collectorUserId]/route.js:12-13` were added **without importing `requireActiveSubscription` (or `requireAccountType`)**, causing all 5 endpoints to crash with `ReferenceError` (HTTP `500`) on every invocation.
