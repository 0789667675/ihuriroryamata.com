# 03 — Complete Route, Page, Workspace Tab, and UI Inventory

## 1. Architectural Routing Model

The application uses a hybrid routing architecture:
1. **Next.js App Router Segments (`app/**/page.tsx`)**:
   - Public marketing landing page (`/`).
   - Authentication routes (`/login`, `/register`, `/forgot-password`, `/verify-email`, `/verify-email-change`).
   - Single authenticated dashboard route (`/dashboard`), plus system routes (`/robots.txt`, `/sitemap.xml`, `app/error.tsx`, `app/loading.tsx`, `app/not-found.tsx`).
2. **Client-Side Workspace Tab Routing (`/dashboard?tab=<tabId>` in `app/workspace.tsx` + `lib/workspace-navigation.js`)**:
   - All authenticated operational, accounting, settings, and Super Admin views are rendered inside `app/workspace.tsx` (`4,418` lines) controlled by the `tab` state synchronized with the URL `?tab=` query parameter (`resolveWorkspaceUrlTab` / `buildWorkspaceTabHref` in `lib/workspace-navigation.js:48-115`).
   - Role-based tab allowlists (`ROLE_TABS` in `lib/workspace-navigation.js:3-24`):
     - **Collector (`COLLECTOR`)**: `dashboard`, `milk`, `farmers`, `deductions`, `settlements`, `ukwezi`, `reports`, `billing`, `notifications`, `settings` (10 tabs).
     - **Collection Center (`COLLECTION_CENTER`)**: `dashboard`, `centers`, `farmers`, `milk`, `ukwezi`, `reports`, `billing`, `notifications`, `settings` (9 tabs).
     - **Super Admin (`super_admin`)**: `accounts`, `audit`, `config`, `system-health`, `notifications-admin` (5 tabs).
     - **Expired Subscription Restricted Mode**: Restricted to `billing`, `ukwezi`, `reports`, `settlements` (`COLLECTOR` only), `notifications`, `settings`.
